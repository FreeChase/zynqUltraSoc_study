## GPIO初始化

**Q**:在vitis2025.1中，是不是只有一组`GPIO`,初始化好后，其他的通过`pin`脚去控制就行了？


**A**：
这个理解**在 PS（处理系统）端是完全正确的**，但在整个 RFSoC 系统的宏观视角下不够全面。

在 RFSoC（基于 Zynq UltraScale+ 架构）的开发中，GPIO 严格分为两大类：**PS 端原生 GPIO (`gpiops`)** 和 **PL 端扩展 GPIO (`gpio` / AXI GPIO)**。它们的控制逻辑是不同的：

### 1. PS 端原生 GPIO (驱动对应 `gpiops`) —— 你的理解完全正确

对于 RFSoC 的 ARM 核心自带的硬件 GPIO 控制器，**物理上确实只有一个控制器实例**。

* **初始化：** 在你的代码中，你只需要对这个总控制器进行**一次初始化**（在 Vitis 2025.1 中通常传入该控制器的物理基地址，如 `0xFF0A0000`）。
* **控制引脚：** 初始化完成后，所有的引脚操作（设置方向、读写电平）都复用这一个实例句柄（Handle），你只需要传入不同的 **全局 Pin Number（引脚号）** 即可。
* **底层架构：** 虽然只有一个控制器，但它在内部被划分为了 6 个 Bank：
    * **Bank 0 ~ 2 (MIO)：** 直接连接到芯片的物理管脚（通常是 Pin 0 到 Pin 77）。
    * **Bank 3 ~ 5 (EMIO)：** 这些引脚不直接出芯片，而是路由到了 PL 端，交给 FPGA 逻辑使用（通常是 Pin 78 及以后）。
    * **结论：** 无论你是控制板载的 MIO 物理引脚，还是控制路由到 PL 端的 EMIO 引脚，逻辑是一模一样的，只要算对 Pin Number 就行。

### 2. PL 端扩展 GPIO (驱动对应 `gpio` / AXI GPIO) —— 有多组，需分别初始化

如果硬件工程师觉得 PS 端的 MIO 或 EMIO 不够用，或者需要跟特定的逻辑模块强绑定，他们会在 Vivado 的 Block Design 中添加 **AXI GPIO IP 核**。

* **有多组：** 硬件工程里拉了几个 AXI GPIO IP 核，系统里就会有**几组完全独立的 GPIO 控制器**。
* **初始化：** 每一个 AXI GPIO 都有自己独立的基地址（比如一个在 `0xA0000000`，另一个在 `0xA0010000`）。在 Vitis 2025.1 中，你需要为每一个 AXI GPIO 分别定义实例句柄并**分别进行初始化**。
* **控制引脚：** AXI GPIO 没有全局 Pin Number 的概念。它按 **Channel（通道）** 和 **Bit（位）** 来控制。一个 AXI GPIO IP 最多有 2 个 Channel，每个 Channel 最多 32 bit。读写时，你需要指定操作哪个实例的哪个 Channel。

---

### 总结给 BSP 的建议

在 Vitis 2025.1 这种基于设备树 (SDT) 的架构下，确认引脚归属的最稳妥方法是去查阅生成的 **`xparameters.h`** 或者直接看 **System Device Tree (SDT)** 的节点：

* 如果你要操作的引脚挂在 `psu_gpio_0` (基址通常是 `0xff0a0000`) 下面，那就**只初始化一次**，后续全靠不同的 Pin Number 寻址。
* 如果你要操作的引脚挂在类似 `axi_gpio_0`、`axi_gpio_1` 的节点下，那它们就是**不同的硬件外设**，必须用不同的基地址分别初始化，然后通过 Channel 和掩码（Mask）来控制不同的引脚。
